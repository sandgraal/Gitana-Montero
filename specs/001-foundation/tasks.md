# Tasks 001 — Gitana Foundation

Task breakdown for `spec.md`, ordered per `plan.md`. Every task cites the
acceptance criteria it satisfies. `[TEST]` tasks author failing graders
**before** their paired `[PLATFORM]` task, by a separate agent instance
(AGENTS.md separation rule). `[CONTENT]` tasks ship both locales in one PR and
get concurrent fact-check + bilingual-edit passes. `[DESIGN]` tasks are run by
the conductor with the owner in the main session (Claude Design Artifact — not
a worktree subagent); deliverables merge via a normal PR. Commit messages
reference this spec: `type(scope): …, refs specs/001-foundation`.

The eligible frontier = every unchecked task whose predecessors (same section,
or explicitly named) are checked. `/conduct next` dispatches the whole frontier.

  **WHAT CONTENT AUTHORS MUST KNOW:** codes are stored as stamped — uppercase alphanumerics joined by single hyphens (`CODE_PATTERN` is `TAXONOMY_ID_PATTERN`'s shape with the case inverted, so `V45W-` and `V45--W` are rejected), at most `CODE_MAX_LENGTH` = 32 characters — so `S` and `s` cannot become two rows; a `vin-code`'s code must *fill* the positions it claims (a 5-position range with a 1-character code is rejected), may not contain `I`, `O` or `Q` (ISO 3779 excludes them; that rule is what catches `O`-for-`0`), and **may not contain a hyphen at all** — a VIN is strictly alphanumeric, hyphens belong to stamped option codes (`MB-000001`), and a hyphen counts toward the length, so before this rule a hyphenated code could *satisfy* the position-fill check while standing for fewer real VIN characters than its range claimed (PR #63, Copilot — caught after two review rounds missed it).   - **Authoring contract for T403/T404/T405** — the shapes' semantics, written here because content authors will hit every one of them. Full reasoning lives in `src/schemas/problems.ts`'s docstrings; this is the operative summary.
    - **Ids join the two halves.** Symptoms, causes, diagnostic steps and fix paths each appear **twice**: as ids (plus their numbers/references) in shared `data`, and as phrases keyed by the *same* ids under `prose.en.<field>` and `prose.es.<field>`. The id sets must match exactly in both locales — a missing phrase and an orphan phrase are both build errors naming the id. Ids are lowercase ASCII kebab-case and are entry-local (there is no shared symptom taxonomy; T402 builds its index from these).
    - **Slugs live in `prose.<locale>.slug`**, ASCII kebab-case, no accents (`tensores-de-barra-estabilizadora`, never `tensóres…`). Never a top-level `data.slug` — Astro's loader would read that as the entry id. Collisions inside a locale fail the build at `getStaticPaths` (I18N-05).
    - **Every diagnostic step must state what a result means**, as data: `rulesIn` / `rulesOut` are arrays of **cause ids**, at least one id between them, every id declared in `causes`. The prose for a step is only the *action*. Consequence: if a step rules something in or out, that something is a root cause and belongs in `causes`. A step is unwritable while `causes` is empty.
    - **Causes are ranked by array order**, most likely first. A per-cause `confidence` is optional and may never be **weaker** than the entry's own tier — PRB-04's caveat is rendered from the entry tier, so a weak cause under a strong entry would show a guess with FSM authority. If a cause really is weaker, lower the entry's tier.
    - **Cost is a band, never a figure**: `{ from, to? }` over `minimal < moderate < significant < major`, rendered `$ … $$$$` / `$–$$`. **Time** is a real quantity (`{ value | min+max, unit: "min" | "h" }`) and **difficulty** is 1–5.     - **Severity ladder** (`PROBLEM_SEVERITIES`, worst first): `safety-critical` (ignoring it can hurt someone) › `damaging` (it destroys something else) › `stranding` (immobilises, nobody hurt) › `degrading` (works, worse) › `cosmetic`. It is about *consequence*, not cost and not likelihood.
    - **Drivability triage rubric (PRB-05) — the safety judgment.** `drive-normally` = the fault changes nothing about how to drive. `drive-gently-repair-soon` = drivable now, but driving it *as usual* makes the outcome worse or riskier (the failure progresses under load, speed or heat). `do-not-drive` = driving it risks a sudden loss of control, a fire or an injury, **or** turns a repairable fault into a destroyed component — the truck may well start and move, that is not the question. `tow-only` = it cannot be driven at all, or moving it under its own power is guaranteed to destroy something. **The `drive-gently` / `do-not-drive` line is the one that costs a reader in both directions** (over-warning strands someone and teaches them to ignore the banner; under-warning is the failure this site exists to prevent). **When the honest answer is "it depends", the entry is scoped too widely** — split it, or state the worse of the two and explain the split in prose.
